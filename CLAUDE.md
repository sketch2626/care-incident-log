# Mary's Porch (Operation Save Grandma)

Mary's Porch is a companion for nursing-home residents: Mary and Sam, two 1950s robots on a porch swing, who residents talk with as friends. A formal care log and state reports are built in. The code still says Care Incident Log. It's open source (GPL-3.0) at github.com/sketch2626/marys-porch, and the goal is a downloadable app on every eligible resident's laptop, starting with one North Carolina facility.

## Read first
This is Andy's mission, not a demo. Andy is a 43-year-old resident of a North Carolina nursing home who builds this mostly by voice, with AI and no computer-science degree: this is what AI is for.
1. **`docs/mission.md`:** the spirit every session must keep.
2. **`docs/decisions.md`:** Andy's standing decisions (D numbers), each with its guard test. Check every brief against it, and stop and ask before breaking one.
3. **`docs/how-we-work.md`:** the process. It covers the hub on Andy's account, workers on the second account, Sonnet and Haiku helpers, testing, publishing, boards and the browser rule. Run the `token-saving` skill at the start of every task.
4. **`docs/status.md`:** what's happening now, what's waiting on Andy, and what's next. What's ahead in detail is in `docs/mary-roadmap.md`.

Rules live only in `docs/decisions.md` and `docs/how-we-work.md`. Notes (status, the roadmap, plans, briefs and the archive) hold facts and link to the rules. Private facts stay out of the repo (D16): Andy's health and personal plans live in the hub's memory and in `private/` (gitignored).

## Where things live
- **`server.py`:** a stdlib-only Python server on 127.0.0.1:8765. SQLite at `%APPDATA%\CareIncidentLog\incidents.db` (override with env `TRACKER_DATA`), with daily backups in its `backups\`. The old project `data/` folder is copied there once (until the new log has incidents) and left in place. Soft delete only (`deleted_at`). Mutating API calls need the header `X-Tracker: 1`.
- **`web/`:** vanilla HTML, CSS and JS. The care log screens follow design "C" from `mockups/` (approved 2026-10-23): the home screen has a summary sentence, a "Just tell me what happened" mic and 9 category tiles, and there are add, saved, list, report and My info screens. They're built for residents 65-95 (text ≥20px, targets ≥64px). Andy Flow parts show only when the resident has turned on "Connect Andy Flow" in My info, and that switch shows only when Andy Flow is installed.
- **`web/mary/`:** Mary's window (`/mary.html`): `app.js` (the talk loop), `talklive.js` (Live), `voiceout.js`, `captions.js`, `screens.js` (the deeper screens beside her, M18), `skills.js` and `face.js` (today's face, which the porch scene replaces, M24).
- **Her brain:** `mary.py` with `mary/instructions.md` (full), `mary/lean.md` and `mary/leaner.md`, behind the test-only setting `mary_brain` (D19). `voices.py` handles Gemini Live, Gemini TTS and Kokoro, and `wakeword.py` the on-laptop "Hey Mary" (Vosk). `memory_core.py` keeps her memories in `mary/memories.db` (D22), and `memory_dates.py` the dates for reminders.
- **Skills:** `skills_core.py` and `skills/` (`docs/skills-design.md`, `docs/how-to-make-a-skill.md`).
- **`send_gate.py`:** the hard-wired yes for saving, sending and plain orders (D8, D12).
- **`speech.py`:** on-device speech-to-text (faster-whisper base.en, model in `models/`, sounddevice mic). Routes `GET /api/listen` and `POST /api/listen/start|stop`.
- **`assist.py`:** the optional Gemini "smart helper" (the resident's own key, off by default; the key is never sent to the page). `POST /api/tidy` sorts free text: Gemini if it's on, otherwise the offline `guess_incident()`.
- **`secret_store.py`:** secrets in Windows Credential Manager, each entry named by a hash of the data folder, so a scratch install never sees real ones. The Gemini key and the email account live here, never in `settings` or a backup. Tests get an in-memory backend from `tests/helpers.py`.
- **`mail_core.py`:** email from the resident's own Gmail or Yahoo (TLS, app password). `ctx.send_mail` needs a one-time ticket that only the core can mint, plus `needs.send_mail` and `"slow": true` on the card. Only `send_gate.py`'s path mints one: `ctx.send_now`, after the resident's own "send it" or the quiet tap (board D2b in `docs/messaging-plan.md`), and the five-second Undo (M15c). Addresses live in the address book, the one place one is kept (D10). Gemini works from names. It gets a detail only when the resident says one, or when `read_detail` gives a saved one because their own words asked (M19). `mail.log` keeps when, a short hash of the address and the result, never the address or the content. `memory_core.scrub_details` keeps emails, phones, street addresses and book values out of her memories, talk history and the other text logs.
- **`address_book.py`:** the secure address book (M19), a core module.
  - `mary/addressbook.db` holds one AES-256-GCM sealed row per person, names included, with `secure_delete` on. It's never in `backups\` or a report. The key is `address_book_key` in `secret_store.py`.
  - A missing key or `cryptography` package locks the book: no plain fallback, nothing wiped, and no new key over existing rows. There's one rolling copy, rewritten at once after a forget.
  - A helper's copy (a `.carebook` file, unlocked with six words from `book_words.txt`) is how a book moves to a new laptop.
  - Skills reach it only through `ctx.people` with `needs.contacts`, and get handles, never values; `needs.contacts_full` is for `messages` alone. `book_move.py` moved M15c's contacts out of `incidents.db` and its dated backups once. Book birthdays are `dates` rows with `source='book'`.
  - "Forget Sarah" reaches her card, reminders, memories and logs; "forget everything" leaves the book.
- **`reports.py`:** formal state reports: `GET /report` (printable, with attestation and signature lines) and `GET /api/export.xlsx`. The CMS F-tag citations were verified 2026-10-23 and re-checked 2026-10-30 against Appendix PP Rev. 232 (`docs/speakup-review.md`). F600 (neglect) is added only for 3 or more of one category in the period. `helped_by` (set only by the form, M18) prints as one line from `helped_note()`, apart from the statement.
- **The Andy Flow inbox:** **off by default** (setting `andyflow_enabled`, 2026-10-28, 2eba502). When it's off, nothing opens `%APPDATA%\Andyflow\history.db`, and the MCP's Andy Flow tools answer "link is off". A log that already holds `andyflow-*` incidents (Andy's) is switched on once by `init_db`. When it's on, it reads `history.db` read-only, and dictations or notes starting with "Incident" (or notes in a folder containing "incident") appear for one-click add. The "Update from Andy Flow" button (`POST /api/inbox/import`) logs every new one at once, using `guess_incident()` in `server.py` (category, wait, never-came, severity).
- **Claude's access to the real log:** the `care-incident-log` MCP (`mcp_server.py`, registered in `.mcp.json`), never screenshots. Tools: `tracker_summary`, `list_incidents`, `add_incident`, `update_incident`, `remove_incident`, `andy_flow_inbox`, `update_from_andy_flow`, `dismiss_andy_flow_item` and `search_andy_flow` (every dictation and note, to find care problems not marked "Incident"). The MCP is for Claude on Andy's machine only, and isn't part of the resident installer.
- **Tools and tests:** `tools/` holds the benches (`brain_bench.py`, `talk_bench.py`, `wake_bench.py`), the model downloads and `worker_context.py`; `bench/` holds the bench cases and results. Tests are in `tests/`, run with `python run_tests.py -q` (`docs/how-we-work.md`, "Testing").
- **Run:** `Start Mary.bat` (Mary's window: `packaging\.venv\Scripts\pythonw.exe desktop.py --mary`), `Start Incident Tracker.bat`, or the preview config `incident-tracker` in `.claude/launch.json`.

## Desktop app (beta)
- **`desktop.py`** is the app's entry. It starts the server in a thread (port 8765, or any free port if that's taken) and shows it in its own pywebview/WebView2 window. If WebView2 is missing, it opens the default browser instead. Closing the window quits. `--mary` opens Mary's window, maximized with a title bar (D25).
- **Build:** double-click `packaging\build.bat`. It makes `packaging\.venv`, installs the pinned `packaging\requirements.txt` and runs `packaging\build.py`. Output in `dist\`: `CareIncidentLog-Setup-<ver>.exe` (Inno Setup, per-user, no admin, Start-menu and desktop shortcuts) and `CareIncidentLog-<ver>-portable.zip`. The version is `VERSION` in `version.py`.
  - It bundles `web/` (with `web/mary/fonts/`), the three brain files and the speed check's clip from `mary/`, `skills/`, vosk, and three models under `_internal\models\`: faster-whisper base.en, Kokoro and the Vosk small English model. When `models/` is missing, `build.py` downloads each one with `tools/get_*_model.py` and a SHA-256 check.
  - v0.5.0 (2026-11-02): installer 336 MB, zip 401 MB.
  - The shortcuts are "Mary" (`--mary`, confirmed by Andy 2026-11-05) and "Care Incident Log".
  - Never bundled: `mcp_server.py`, `.mcp.json`, `mockups/`, `docs/handoff/`, `bench/`.
  - The installer needs Inno Setup 6; the zip is built without it.
- `packaging\installer.iss` is the installer script, and `packaging\make_icon.py` makes `icon.ico`. Uninstalling leaves the data folder alone.
- **Test a build without touching real data:** set env `APPDATA` to a scratch folder and `TRACKER_PORT=8799`, run the exe, use the API, close it and run it again. Silent install: `Setup.exe /VERYSILENT /DIR=<folder>`.
- **Not yet:** code signing. The unsigned exe gets a SmartScreen "More info → Run anyway" prompt.
- **Dev tools on this laptop:** Node.js LTS v26 (`C:\Program Files\nodejs`; a shell opened before the install may need it added to PATH), GitHub CLI 2.103 (`gh`, signed in as sketch2626; commits use GitHub's no-reply address), Inno Setup 6 (per-user, `%LOCALAPPDATA%\Programs\Inno Setup 6\ISCC.exe`), Git and Python 3.12.

## Longer term
- **The backend** (`docs/backend-plan.md`) is built to medical and enterprise security standards. It covers passkey sign-in, named or anonymous sending, mood check-ins, and de-identified research data for universities (with consent and IRB). Identity is kept apart from data, and a facility is shown only once 5 or more residents there take part, keyed by CMS provider number.
- **Funded helpers** set up residents' laptops and optional AI keys (`docs/pilot-checklist.md`).
