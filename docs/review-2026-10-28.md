# Code review, 2026-10-28 (before Andy's first try of Mary)

A full review of the app before Andy opens Mary for the first time. An Opus worker ran it, with Sonnet helpers doing the review and coding one area at a time (one Haiku task crashed and was finished by hand).

Tests: 170 tests with 5 BUG skips before → 254 tests and no skips after (236 after the review, plus the Andy Flow follow-up below). The suite also passed 20 runs in a row, after fixing a flaky connection reset.

Not reviewed here: branch `wip/report-to-state` and `mockups/`. Nothing ran in a real window: no desktop.py, browser or screenshots. The checks used:
- the in-process test server with scratch data
- Node, from Cursor's bundled runtime, to syntax-check the pages
- fake-DOM harnesses that load the real `app.js` and `firstrun.js`

## What was checked

**Mary path (a):**
- `Start Mary.bat`, `desktop.py --mary`, `power.py` and `/api/power`
- `mary.py` and `mary/instructions.md`
- the `/api/mary/*` and `/api/listen*` routes, and `speech.py`
- `web/mary/` (`app.js`, `firstrun.js`, `face.js`, `mary.html`, CSS)

What was looked at:
- **The pages against the server:**
  - JS syntax.
  - Every referenced file exists, and every `$('id')` matches an element.
  - Every fetch matches a route and its JSON fields.
  - Stream parsing: split lines, split UTF-8, no final newline, an error line, a server that has gone.
- **Error paths:** no key, a bad key, offline, a Gemini timeout, no mic, the speech engine missing, a slow model load, server 500s, WebView2 missing, `packaging\.venv` missing.
- **Voice and timers:** voices loading late, the online-voice fallback, rate and volume, cancel on a new turn, idle sleep and dim, Wake Lock re-acquire, KeepAwake release.
- **The way out:** Close on every screen, and that no key combo is needed.
- **Brain:** emergency and self-harm phrases, the "write it down" offer, memory saves, names, and that the key is never in a response or file.

**Rest of the app (b):**
- **Server security:** the Host check, `X-Tracker`, path traversal (17 variants), framing.
- **Data integrity:** soft delete, edits, backups, migration, imports, validation, bad bodies, concurrency.
- **Reports and exports:** HTML escaping, xlsx/csv formula injection.
- **Smart helper and MCP:** `assist.py`, plus `mcp_server.py`'s robustness and read-only Andy Flow access.
- **Home page:** `web/app.js`, `index.html`, `styles.css` (the API contract, routing, the mic flow, XSS, ≥20px text, ≥64px targets).
- **Installer:** `packaging/`.

**Known BUG skips (c):** `guess_incident()`.

## Follow-up the same day (Andy approved): Andy Flow link off by default

Before, anyone who installed Andy Flow later was connected without choosing to.

| Commit | Change |
|---|---|
| 2eba502 | **Server and MCP:** new setting `andyflow_enabled`, off by default. When it is off: `history.db` is never opened (only checked for existence); `/api/inbox` returns `{available: false, enabled: false, installed, items: []}`; import adds nothing; dismiss returns 400; the MCP Andy Flow tools answer "The Andy Flow link is off". `init_db` turns the link on once if the setting was never saved and the log already holds `andyflow-*` incidents (Andy's laptop). New installs stay off, and a saved value is never changed. |
| f8fef18 | **My info:** a "Connect Andy Flow" switch, shown only when Andy Flow is on that computer. While the link is off, every Andy Flow part of the page stays hidden. |
| 47c78f5 | **Found while testing:** the server sent a save's reply before committing it, so a page reading the log right away could miss the new entry. It now commits first. This fixed a second flaky test (20 clean runs). |

If Andy's log has no entries imported from Andy Flow, he turns on "Connect Andy Flow" once in My info.

## Open items, ranked (judgment calls and things not fixed)

**Check during Andy's first try:**
1. **Nothing has run in a real window yet.** Still unconfirmed:
   - full screen;
   - the Close button through the pywebview bridge;
   - the autoplay voice;
   - which voices WebView2 offers;
   - the keep-awake;
   - the layout at his screen size.

   If the window ever gets stuck full screen, the hub can close it for him (stop the `pythonw … desktop.py --mary` process), so he never needs Alt+F4. `desktop.log` in the data folder records window errors.
2. **Listening timings, tuned with Andy:**
   - 1.4 s of quiet ends his turn (`app.js`, `quiet_s >= 1.4`). A slow or breathless speaker may be cut off; about 2.2 s may suit him better.
   - Soft voices against TV noise are untested with a real mic.

**Medium:**
3. **Double launch.** Double-clicking `Start Mary.bat` twice opens two full-screen Marys, the second on another port. A single-instance guard would stop this (judgment).
4. **No Mary shortcut in the installer.** `installer.iss` makes only "Care Incident Log". Inside it, the "Talk to Mary" link opens Mary in a normal window, without full screen, keep-awake or Close. Suggest adding a "Mary" shortcut with `--mary`.
5. **The Gemini key is stored in plain text** in the DB and every daily backup. It is never sent to the page. This is backend plan phase 1 (encrypt the local log).
6. **The smart helper replaces the resident's own words** with Gemini's tidy version; the raw words aren't kept. For evidence, keeping the original may matter (judgment).
7. **Cold first talk on a slow laptop.** If the voice model is still loading after 60 s, she says "waking up my ears" and those words are lost. Saving the audio for the next try was not built.
8. **The installer has not been rebuilt.** Whether the native DLLs (sounddevice, av, pythonnet) bundle correctly is unverified (Next step 5).

**Low:**
9. **The browser fallback** (no WebView2) keeps a hidden `pythonw` running, and each launch picks a new port, which resets the greeting rotation.
10. **Mary's hello save fails** (server error) and she says "I didn't quite catch that" instead of "I can't save that right now".
11. **A long caption scrolls to its end,** hiding the start of a long reply.
12. **From Mary's "My notes" page there is no Close.** The way back is the "Talk to Mary" link.
13. **A mic plugged in after Mary opens** needs a restart, because typing-only mode is decided at load.
14. **"I fell last year" shows the emergency screen.** This is kept on purpose: over-alerting on falls is safer.
15. **Future incident dates are allowed** (judgment).
16. **`Start Mary.bat` with no venv and no `pythonw`** on PATH shows a Windows "cannot find" message.
17. **`web/mary/demo.html` ships in the installer.** It is harmless.
18. **Opening a WAL-mode Andy Flow DB read-only** leaves `-wal`/`-shm` files next to it. The data is unchanged.

**Checked and fine:** an MCP reviewer suspected the Andy Flow column `app_name` was missing. It exists in Andy Flow's real schema (`database.py`); only the test fixture lacks it.

Every window gets `AppApi.paste_text()` (Windows clipboard via ctypes, trimmed, never logged); Mary's window keeps `close_window`. Tests: `tests/test_desktop.py`.
   - c1cadca, `web/`: a big **Paste** button beside My info's key box ("Key pasted. Tap Save."; the browser fallback uses `navigator.clipboard.readText()` with a kind message). Mary's "Open My info" and notes links carry `?from=mary`, and My info then shows a big **Back to Mary/Sam** button.
   - Not yet seen in a real window: the trimmed menu and the Paste button.
