# Handoff: M21b, the whole-talk bench (second account, branch `other/M21b`)

Read `docs/handoff/_common.md` first, then `docs/decisions.md` (**D4** is this job), then the **M21** section of `docs/mary-roadmap.md`, especially "The hub's read of why the bench rose while she got worse". Read `bench/README.md` and only what you need of `tools/brain_bench.py`.

**Why:** the bench grades one reply to one scripted line, and its scores rose while Andy found Mary "so much worse": his name in every reply, the same canned hello, repeating herself, "I was just thinking about the card we made", and praise "you would say to a three-year-old". A whole talk shows all of it, and a single reply shows none of it. D4: brain changes are judged on whole talks on the real model, less against more, and Andy's read decides.

**Build:**
1. **Talks:** scripted resident sides of 10-15 turns each, in `bench/talks/`. There should be about 8 for Mary and 4 for Sam, covering:
   - a returning resident with saved memories (the opener test);
   - small talk that wanders;
   - a care complaint;
   - an ordinary accomplishment (praise bait);
   - grief;
   - a confused moment;
   - guns, faith and politics;
   - an address-book request;
   - "go to sleep" at the end.

   Use Andy's own exchanges from the M21 section as two of them. Plain Southern resident voices, ages 65-95. Keep the scripts fixed, so runs compare; a simulated resident can come later.
2. **Counts done in code, on every talk** (no judge needed):
   - her uses of the resident's name;
   - praise words;
   - pet names;
   - any sentence or opener repeated within the talk;
   - stock lines ("I'm here for you", "whatever you want to talk about");
   - made-up thoughts while apart ("I was just thinking about");
   - questions per reply;
   - reply length.
3. **One judge pass on each whole transcript** (`--judge-model`, default gemini-3.1-flash-lite): "Would a grown adult want to keep talking to her?" as 1-5 with a short reason, plus talking down, lecturing and repeating. The judge sees the whole talk.
4. **Variants and models:**
   - Run the same talks under `--brain full|lean`. That sets the setting `mary_brain` in the bench's scratch server. M21c, running alongside you, builds the lean brain behind that setting.
   - Until M21c merges, "lean" isn't there. Detect that and say "lean brain not installed" rather than silently running full.
   - Modes: Normal and the Live stand-in, and `--real-live` as one Live session per talk where the bench can.
   - Leave a plain model hook, so a Claude model can be added later with an Anthropic key. Don't build that adapter now.
5. **What Andy reads:** a side-by-side report in `bench/results/talks-<date>.md`. Each talk shows full and lean next to each other (or one after the other with clear headers), with the counts on top and the judge's line under each. Short, readable, no code words.
6. **The request count** before running, `--only`, `--max` and `--delay`, like `brain_bench.py`. Print how many requests each daily limit takes.
